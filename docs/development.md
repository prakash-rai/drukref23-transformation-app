# Development

For developers working on the app. For coding rules and conventions see [AGENTS.md](../AGENTS.md).

## Prerequisites

- Node.js 22.13 or later (the tests build GeoPackages with `node:sqlite`) and pnpm (`corepack enable`)
- Network access to `https://cadastral.systems.gov.bt` (office network or VPN) for anything that talks to ArcGIS

## Run locally

```bash
pnpm install
cp .env.example .env     # add ARCGIS_USERNAME and ARCGIS_PASSWORD — see configuration.md
pnpm dev                 # http://localhost:3000/drukref/
```

`http://localhost:3000/drukref/api/health` shows the service check directly. If the page says *Service unavailable*, the red banner gives the reason; [deployment.md](deployment.md#troubleshooting) explains each message.

## Scripts

| Command | What it does |
| --- | --- |
| `pnpm dev` | Dev server with hot reload on port 3000 |
| `pnpm test` | Unit tests (no network, no credentials) plus documentation drift checks |
| `pnpm test:live` | Checks against the **real** ArcGIS Server using `.env`: sign-in, service metadata, and a full job with `deployment/data/drukref03-test-upload.zip` |
| `pnpm typecheck` | TypeScript |
| `pnpm build` | Production build into `.output/` |
| `pnpm check` | `typecheck` + `test` + `build`. It must pass before a change is merged or deployed. |
| `pnpm start` | Runs the production build (`node .output/server/index.mjs`) |

`src/routeTree.gen.ts` is regenerated by `pnpm dev` and `pnpm build`. Commit it with any route change.

## Tests

| Area | File | Covers |
| --- | --- | --- |
| Dataset inspection and packaging | `src/lib/upload-package.test.ts`, `dataset-state.test.ts` | Shapefile sidecars, ignored-file reasons, ZIP wrapper folders, manifest, inclusion toggles |
| File selection | `src/lib/file-check.test.ts` | Incomplete Shapefile and unsupported-format notices, folder fallback |
| Projection pre-check | `src/lib/crs.test.ts`, `projection-check.test.ts` | WKT1/WKT2/ESRI parsing, DrukRef03 matching, GeoPackage metadata via a generated SQLite file, user-visible messages |
| Progress display | `src/lib/projection-status.test.ts` | Step detection, success/failure counts |
| UI state | `src/lib/upload-workflow.test.ts` | Health reason, message de-duplication, clearing activity |
| Browser API client | `src/lib/arcgis-upload.test.ts` | Base path, submit errors (JSON and HTML), polling retries, terminal job states, time-out |
| ArcGIS client | `src/server/arcgis-client.test.ts` | Token caching/expiry/concurrency/renewal, error translation (403/404/498/499/HTML/network), upload/submit/status/result, job-ID validation, result URL re-rooting |
| Upload streaming | `src/server/arcgis-service.test.ts` | Size limit (declared and streamed), empty/non-ZIP bodies, temp-file clean-up on success, failure and abort |
| HTTP endpoints | `src/server/api-routes.test.ts` | Status codes, JSON bodies, download headers |
| Documentation | `tests/docs.test.ts` | Config/doc sync, Markdown links, IIS rule, changelog |
| Live ArcGIS | `src/server/arcgis.live.test.ts` | Only run by `pnpm test:live` |

Guidelines:

- Inject `fetch`, clocks and sleeps rather than mocking globals. See the fakes in the existing tests.
- Cover the user-visible failure message, not just the happy path.
- Name live tests `*.live.test.ts`. `pnpm test` excludes them.

## Live test

Run it before each release and whenever the ArcGIS side changes (password, permissions, republished service):

```bash
pnpm test:live                       # full check, submits one small job
ARCGIS_LIVE_SKIP_JOB=1 pnpm test:live  # sign-in and service only
```

On Windows PowerShell: `$env:ARCGIS_LIVE_SKIP_JOB=1; pnpm test:live`.
