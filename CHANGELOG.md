# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Every merge to `main` is deployed automatically ([docs/deployment.md](docs/deployment.md#automatic-deployment)). When you mark a release, rename *Unreleased* to the version and date.

## [Unreleased]

### Added

- Continuous integration and deployment with GitHub Actions. Pull requests run `pnpm check` and a Windows test of the deploy script. Merges to `main` are built on GitHub and installed by a self-hosted runner on the server, with an automatic rollback when the new release doesn't start or can't use ArcGIS ([ADR 0004](docs/decisions/0004-windows-service-with-github-deploys.md)).
- The **DrukRef** Windows service (`deployment/windows/`): Node.js runs the app directly, starts delayed after boot, restarts after a crash, and keeps rotated logs.
- `GET api/live`: reports that the app is running without contacting ArcGIS, for deploys and monitoring.
- While the service is unavailable, the page checks again every 30 seconds and turns **Service online** by itself, for example once ArcGIS finishes starting after a reboot.
- Server-side ArcGIS integration (`src/server`, `src/routes/api`). It signs in with `.env` credentials and caches and renews the token. It streams uploads to ArcGIS and results back to the browser.
- A service banner that shows the exact reason the service is unavailable, with **Retry**.
- `pnpm test:live` for end-to-end checks against the real ArcGIS Server.
- Upload validation: size limit (`MAX_UPLOAD_MB`), empty and non-ZIP bodies are rejected.
- IIS reverse-proxy configuration (`deployment/iis/web.config`) and a production runbook.
- The `docs/` folder with architecture, configuration, development, deployment and GP-service guides, ADRs, and this changelog. Documentation drift checks run in `pnpm test`.

### Fixed

- The page no longer scrolls sideways. The hidden file input was 100% wide, which pushed the page past the viewport.

### Changed

- Checking a running job now rides out up to 3 minutes of app restart or ArcGIS outage, instead of giving up after about 10 seconds. Other errors still end the wait after 5 attempts.
- Node.js 24 LTS is required for development and production.
- The app is served under `/drukref/` (`APP_BASE_PATH`) for publication at `https://cadastral.systems.gov.bt/drukref/`.
- ArcGIS target is now `https://cadastral.systems.gov.bt/server` (was `172.30.4.165`).
- Job polling allows up to 60 minutes and tolerates brief network errors.
- The Docker image runs the unit tests during the build. The container binds to `127.0.0.1`, has a health check and log rotation, and is tagged with `IMAGE_TAG`.
- Developer tools are no longer rendered in production builds.

### Removed

- The Docker deployment (`Dockerfile`, `docker-compose.yml`, `.dockerignore`) and the `IMAGE_TAG` setting. Production runs as a Windows service instead.
- The Nginx gateway and the browser-side `/arcgis-*` proxy routes, including the proxy that disabled TLS verification.
- The `generate-routes` and `preview` scripts. The route tree is generated by `pnpm dev` and `pnpm build`, and `vite preview` is not suitable for production.

### Security

- ArcGIS credentials and tokens never reach the browser. Tokens are never placed in URLs.
- Result downloads are restricted to the ArcGIS job output directory.
